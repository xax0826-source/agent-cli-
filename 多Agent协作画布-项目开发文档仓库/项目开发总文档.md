## 1. 项目是什么

本项目暂名 **多 Agent 协作画布**，目标是把多个真实 Agent CLI 会话连接到同一个无限画布中，用户可以创建会话节点、选择节点使用的 CLI 和模型，在两个会话节点之间建立真实连线，查看它们的协作与运行状况。

支持三条交互入口：

1. **全局视图**：将所有层级展开在一张无边界画布上，显示所有会话节点和各自真实连线。子流程以可视化分组容器呈现，跨流程的会话连线逐条展示。
2. **分层视图**：一张父流程图包含多个子流程节点；进入节点可打开子流程图（可继续递归），叶子会话节点则打开会话管理界面。父层的多条底层真实连线汇总成一条**只读聚合连线**，标示来源数量及活动程度。
3. **大纲导航**：用户通过文件夹式树状目录查找任意流程和会话，与两种画布视图共享同一份节点树。

**不可改变的产品约束（来自当前需求）**：用户只允许编辑「会话节点 ↔ 会话节点」的真实连线，不能定义「流程图 ↔ 流程图」连线，也不能从父层聚合连线反向创建底层连接。父层的聚合连接必须纯粹从真实会话边投影推导，不另存成一条业务关系。

**还需确认的产品决策**：线的方向/含义（单向可通信、双向关系或任务依赖）、是否自动执行下游、首批 CLI 清单与模型切换限制、跨流程外部连接在子流程内部的辅助提示。当前文档用“有向消息关系”作为可开发的**建议基线**，不把它表述为已最终确认的需求。技术路线暂建议 Electron + React/TypeScript + 图形组件 + 本地数据库，实施前可以替换。

项目目前是**从零开始的设计阶段**，没有已实现或已验收的应用功能。文档检查工具属于仓库配套工具，不等于应用已完成。

## 2. 整体系统划分

- **01 图模型与真实连线**：维护 Flow、Node 和真实会话边的领域约束。
- **02 双视图投影与画布**：完整显示或按层聚合真实连接；呈现节点与连线明灭。
- **03 大纲导航与会话交互**：按层级定位会话、进入会话页面和选择模型。
- **04 CLI 适配与生命周期**：统一 Agent CLI 接口，管理真实会话及审批。
- **05 协作消息与运行状态**：沿真实边交换消息并跟踪投递、运行与聚合状态。
- **06 数据存储与恢复**：持久化图、真实边、会话及事件，支持重启恢复。

完整系统图见[00 整体总览](流程图/00-整体总览.md)，其图源为[00-整体总览.mmd](流程图/00-整体总览.mmd)。
