## 4. 准备如何开发或改造

对真实边两端分别求当前层的可见直接子节点，映射成不同节点则按有向端点聚合；保留底层边 ID。。实现时：仅展示两个端点都在当前流程后代中的边；相同直接可见节点内部的边隐藏；跨子流程的多条真实边汇成一条只读聚合边。 与 读取投影结果，聚合边不可编辑、不可直接新建、不可删除；进入子流程保持导航路径。。关键异常必须有明确处理结果，不能仅改变画布表现而绕过真实数据校验。

### 投影处理步骤（建议的实现契约）

1. 输入唯一保存的真实边集合 `RealSessionEdge[]`、完整流程树和用户当前查看的 `flowId`。
2. 对每个真实边端点的会话节点，沿 `parentFlowId` 回溯到当前 `flowId`，取得**当前流程的一个直接子节点**（若端点不在当前流程的子树内，则返回空）。
3. 两个端点都映射成功且不相同时，以 `(visibleSource, visibleTarget)` 分组；相同时为当前折叠节点内部关系，在本层不绘制。
4. 为每组生成临时 `ProjectedEdge`，附上底层 `edgeIds`、数量以及运行活跃数；不把这类边写入数据库，也不允许在 UI 上直接添加、删除或改端点。
5. 如果一个端点不属于当前流程的后代，当前局部子流程图不绘制这条跨边。它会出现在双方最低公共祖先流程对应的分层视图上；全局展开视图始终绘制该底层真实边。

**举例**：根流程 R 有子流程 A、B 和叶会话 C；A 内为 A1、A2，B 内为 B1、B2。真实边 `A1→B1`、`A2→B2`、`A2→C`、`B1→A1` 共四条。

| 查看视图 | 实际可见的线 |
| --- | --- |
| 全局展开 | A1→B1、A2→B2、A2→C、B1→A1，四条分别保留 |
| R 的分层视图 | A→B ×2、A→C ×1、B→A ×1，三条只读投影线 |
| A 的分层视图 | 仅 A 内部真实关系；不造出 A→B，也不在 A 内插入 B 的虚拟节点 |

**必须测试的变更**：删除 `A1→B1`，父层的 `A→B` 立即变为 `×1`；移动 A2 到 B 后，在不改变任何真实边的情况下重新计算可见聚合关系；没有真实边时父层不出现多余连线。
