## 6. 注意事项与验证方法

<a id="verification"></a>

<a id="verification-01"></a>

**验证记录 DOC-01（首次建库）：**

- 在仓库根目录执行：`python3 tools/check_docs.py`。
- 实际结果：检查 50 份 Markdown、8 张独立 `.mmd` 图源和 383 个本地链接，返回码 `0`，输出 `[PASS] 文档仓库静态检查通过。`。
- 负向测试 1：临时将一条存在的本地文档链接改为不存在的文件，返回码 `1`，准确报告「本地链接不存在」，随后恢复原文件。
- 负向测试 2：临时修改 `.mmd` 节点标签而不修改 Markdown 展示块，返回码 `1`，准确报告「Mermaid 展示副本与图源不一致」，随后恢复原文件。
- 检查能力：本地文件及章节锚点、有效/废弃任务表七列格式、文首任务进度对应关系、局部前置依赖循环、稳定图与节点编号、图源引用及展示副本一致性、部分实现状态文本。
- 检查范围限制：环境没有 `mmdc`，因此尚未执行 Mermaid 的**完整语法渲染**；实际业务功能验收、节点范围语义与跨提交的真实更改事实不能仅靠静态工具判定，需要人工复核。

- 验证目标：对文档仓库运行检查返回 0；破坏一条链接或 .mmd 同步内容时返回非 0 并指出路径。
- 对新增的产品代码：在真实源码出现后执行单元测试和端到端测试；当前无通过记录。
- 错误处理、兼容和安全行为以节点开发文档的验收标准为准，不用“已写计划”代替实际验收。
